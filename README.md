# Verilog HDL Training Labs

This repository contains the Verilog HDL lab exercises completed during my Digital Design on FPGA training at NTI.
Each lab is organized into its own directory and includes the required source files, testbenches, and simulation-related files.

The labs focus on developing practical skills in **Verilog HDL**, **digital logic design**, **RTL modeling**, and **simulation and verification**.

## Repository Structure

Each lab follows a similar structure:

```text
.
├── lab_01/
│   ├── src/
│   │   └── module.v
│   └── tb/
│       └── module_tb.v
│
├── lab_02/
│   ├── src/
│   │   └── module.v
│   └── tb/
│       └── module_tb.v
│
├── lab_03/
│   ├── src/
│   └── tb/
│
└── ...
```

### Directory Description

* **`src/`** — Contains the Verilog source files for the design/module being implemented.
* **`tb/`** — Contains the Verilog testbench files used to verify the corresponding design.
* **`*.vcd`** — Waveform files generated during simulation when waveform dumping is enabled.

Each lab is intended to be **self-contained**, so its source code and testbench are located within the same lab directory.

## Tools Used

The simulations in this repository use the following open-source tools:

* **Icarus Verilog (`iverilog`)** — Verilog compiler/simulator.
* **VVP (`vvp`)** — Executes the compiled simulation generated by Icarus Verilog.
* **GTKWave (`gtkwave`)** — Waveform viewer used to inspect simulation results when VCD waveform dumping is enabled.

## Running a Lab

Navigate to the desired lab directory:

```bash
cd lab_01
```

Compile the design and testbench using `iverilog`:

```bash
iverilog -g2012 -o simulation src/module.v tb/module_tb.v
```

Run the compiled simulation:

```bash
vvp simulation
```

If the testbench generates a waveform file (`.vcd`), it can be opened using GTKWave:

```bash
gtkwave waveform.vcd
```

### Example

A typical lab may contain:

```text
lab_01/
├── src/
│   └── alu.v
└── tb/
    └── alu_tb.v
```

The simulation can be compiled and executed with:

```bash
iverilog -g2012 -o alu_sim src/alu.v tb/alu_tb.v
vvp alu_sim
```

If the testbench contains waveform dumping, for example:

```verilog
$dumpfile("alu.vcd");
$dumpvars(0, alu_tb);
```

then the generated waveform can be viewed with:

```bash
gtkwave alu.vcd
```

## Testbenches

Each lab includes a testbench designed to exercise the functionality of the corresponding Verilog module.

Depending on the exercise, the testbench may include:

* Input initialization
* Multiple test cases
* Clock generation
* Reset testing
* Different operating modes or control signals
* Boundary and corner cases
* `$display` / `$monitor` output
* VCD waveform generation

The testbenches are primarily intended for **functional verification through simulation**.

                  ▼

## Requirements

Install the following tools before running the simulations:

```text
Icarus Verilog
VVP
GTKWave
```

On Linux, these can typically be installed through the system package manager. For example, on Debian/Ubuntu-based systems:

```bash
sudo apt update
sudo apt install iverilog gtkwave
```

`vvp` is included with Icarus Verilog.

Verify the installations with:

```bash
iverilog -V
vvp -V
gtkwave --version
```

## Notes

* The simulations use **Icarus Verilog with SystemVerilog support enabled** where required (`-g2012`).
* Compilation commands may need to be adjusted depending on the filenames used in a particular lab.
* GTKWave is only required for labs where waveform output is generated and waveform inspection is needed.
* Generated simulation executables and waveform files may be excluded from version control depending on the repository's `.gitignore` configuration.

## Purpose

The purpose of this repository is to document and practice the concepts covered during Digital Design on FPGA training, while maintaining the exercises in a structured and reproducible format.

Each lab can be compiled, simulated, and inspected independently using the tools described above.
